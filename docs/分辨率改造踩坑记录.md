# 分辨率 / 1024 UI 改造踩坑记录

> 回退基准：**git tag `v3.0.0`**（`a9a1644`，固定 800×600 + `ApplyNativeResolution`，无场内热切换）  
> 新范围：**仅** 登录页、商城页的 1024 资源/布局，**不改** 场内 StatusBar 热切。

---

## 一、目标理解反复跑偏

| 错误 | 后果 |
|------|------|
| 一度按「重新进图才生效」验收，忽略用户要 **图内热切换** | 在 `ApplySysOpt_hook` 里删掉 `set_screen_resolution`，与用户需求相反 |
| 又在热切上叠「对齐 readonly 一次性 `UpdateResolution`」 | 两套模型互斥，补丁互相覆盖 |
| 计划写「不调用整包 `UpdateResolution`」，实现又反复调用 | `RestoreVanilla800` / `UpdateResolution` / `SyncViewport` / kaentake MAX 四套逻辑并存 |

---

## 二、架构层面错误

### 1. 三套子系统未同进同退

- **A** Gr2D 视口（`ScreenResolution`）
- **B** EXE 内存补丁（push 常量、codecave）
- **C** uipath 换 `1024*` 贴图

热切时只改了 A，或 B 只改一半（log 里 `App_W=800` 但 `StatusBar_W=1024`），底栏裂开、商城花屏。

### 2. kaentake「EXE 固定 MAX」与「800 必须原版」冲突

- `PatchStaticResolutionMax` 把 `008CFD50` 等写成 1024 后，**800 登录/底栏仍按 1024 常量建 UI**
- 未在每次热切时用 `SyncViewportPatchConstants(w,h)` 写回当前档位

### 3. 已创建 UI 不会随补丁自动重建

- log 常见：`scr=800` 但 `StatusBar layer=1024x746`
- 只改 EXE 常量 **不等于** StatusBar 控件重布局；场内热切必然残留

### 4. WndMan 锚点逻辑错误

- 800 时旁路 `GetOrgWindow`、不建锚点，1024 再建 → 热切后 `OrgQuickSlot` 残留偏移
- `RelMove(0,0)` 是**相对**移动，1024→800 未 `RelMove(-152,-68)` 撤销 → **快捷键栏画面错位、点击区域仍对**

### 5. 登录阶段切分辨率时机错误

- `set_stage_hook` 在 `set_stage()` **之后** 才 `set_screen_resolution(0)` → 登录 UI 已按错误视口创建
- `Login.img` 换 `1024frame` 与汉化框冲突 → 黄条花屏

### 6. 范围过大

- 同时改：StatusBar、快捷栏、WndMan、地图视野、SysOpt、商城 codecave、登录 frame
- 应收敛为：**v3 稳定 800 场内 + 仅登录/商城 1024**

## 三、实现细节错误

| 问题 | 说明 |
|------|------|
| `nStatusBarY` 算错 | `(h>600)?...:0` 在 600 高时为 0，应为 `h-578` |
| `RestoreVanilla800` 写 `008CFD4B=578` | 与 1024 MAX 补丁打架 |
| 启动 `UpdateResolution` + `RestoreVanilla800` | 与 `set_screen_resolution` 重复、顺序混乱 |
| uipath 过早挂接 | 曾导致 `0x80004005`；应延后到 ResMan/Gr2D 初始化后 |
| `1024backgrnd` 直接 uipath | WZ 写入有损，与全屏底图 codecave 冲突花屏 |
| MSVC 中文注释 `→`、UTF-8 | 编译失败；`Client.cpp` 直接 include `statusbar.h` 与 ZAlloc 重定义冲突 |
| debug log 读 `009F707D+1` | 与 `UpdateResolution` 写的 `009F7079` 等多处并存，易误判 |

## 四、测试与流程错误

- 未固定「先验 800 不退化」就叠 1024 功能
- 用错误验收标准（重新进图）掩盖热切根因
- 多轮改 DLL 未核对 log 关键项：`StatusBar_W`、`OrgQuickSlot`、`layer=` 是否一致

---

## 五、回退后新原则（仅登录 + 商城）

1. **场内永远 v3 的 800×600**（`ApplyNativeResolution`，不挂 `krt/resolution.cpp` 全量 mod）
2. **1024 仅作用于**：
   - `Login.img` / 登录相关 UOL（可选 `1024frame`，需与汉化框对齐）
   - `CashShop.img` + 已有 `CashShopFix*` codecave 的 `myWidth`/`myHeight` 偏移
3. **不做**：场内热切换、StatusBar `1024*`、WndMan 扩展锚点、SysOpt 分辨率下拉（可后续再加）
4. 每步：**800 进图正常 → 只测登录/商城 → 再 commit**
