## 1. 汉化乱码（动态文字全花，静态 UI 正常）

### 现象

- 聊天、角色名、系统提示等**动态文字**变成乱码（如 `禄露脱顺`、`Ã°ÏÕµºONLINE`）
- 小地图、商城、帮助等**静态 UI 文字**仍然正常（来自 WZ 图片，不走 StringPool）

### 根因

北斗客户端底层是**英文 GMS 客户端**，中文依赖 DLL 的 `SwitchChinese=true` + `ReplacementFuncs.h` 中约 900 条字符串池替换。

`ReplacementFuncs.h` 里的汉化字符串以 **GBK 单字节**形式存储。在编辑器里看起来像乱码，例如：

```cpp
{921, "#e Ã°ÏÕµºONLINE »ù±¾²Ù×÷·¨#n\r\n..."}
```

这里 `Ã°ÏÕµº` 对应的字节序列是 `C3 B0 CF D5 B5 BA`（即游戏里显示的「冒险岛」），**不是** UTF-8 中文。

某次用 UTF-8 编辑器保存该文件后，每个字节被扩成 2 个 UTF-8 字节。重编译进 DLL 后变成：

| 状态 | `冒险岛ONLINE` 在 DLL 中的十六进制 |
|------|-----------------------------------|
| 正常 | `C3 B0 CF D5 B5 BA 4F 4E 4C 49 4E 45` |
| 乱码 | `C3 83 C2 B0 C3 8F C3 95 C2 B5 C2 BA 4F 4E 4C 49 4E 45` |

游戏按 GBK 解释这些字节，于是全部显示为乱码。

### 错误做法（勿用）

把 `config.ini` 里 `SwitchChinese` 设为 `false`：

- 乱码会消失，但界面会**变回英文**
- 北斗客户端**没有**完整的中文 `String.wz`，不能靠关汉化来「修复」

### 正确修复

**步骤 1：把 `ReplacementFuncs.h` 从 UTF-8 转回 GBK 字节**

用 Python 一键转换（在项目根目录执行）：

```powershell
py -3 -c "
path = r'ezorsia\ReplacementFuncs.h'
raw = open(path, 'rb').read()
fixed = raw.decode('utf-8').encode('latin-1')
open(path, 'wb').write(fixed)
print('done, size', len(fixed))
"
```

转换后文件中应能看到 `Ã°ÏÕµº` 这类「假乱码」字符，这才是正确形态。

**步骤 2：工程已加入编译选项（`ezorsia.vcxproj` Release\|Win32）**

```xml
<AdditionalOptions>/source-charset:.936 /execution-charset:.936 %(AdditionalOptions)</AdditionalOptions>
```

- 无 BOM 的 `ReplacementFuncs.h` → 按 GBK（代码页 936）编译
- 带 UTF-8 BOM 的 `Client.cpp` → 仍按 UTF-8 编译（MSVC 认 BOM）

**步骤 3：确认配置并重新编译部署**

```ini
; config.ini
SwitchChinese=true
```

```powershell
& "C:\Program Files (x86)\Microsoft Visual Studio\2019\BuildTools\MSBuild\Current\Bin\MSBuild.exe" `
  "ezorsia.sln" /p:Configuration=Release /p:Platform=x86

Copy-Item out\Release\ijl15.dll <BeiDou-Client 目录>\ijl15.dll -Force
```

### 验证 DLL 字符串是否正确

对比新旧 DLL 中 `ONLINE` 附近的字节：

```powershell
py -3 -c "
```

## 2. 编辑 `ReplacementFuncs.h` 的规范

| 操作 | 建议 |
|------|------|
| 用 Cursor / VS Code 打开 | 右下角编码选 **GBK** 或 **Western (ISO-8859-1)**，**不要**选 UTF-8 |
| 看到 `Ã°ÏÕµº` 一类字符 | 正常，不要「修正」成 UTF-8 中文 |
| 新增汉化条目 | 用 GBK 字节或从已有条目复制格式；改完按上面步骤验证 DLL |
| `Client.cpp` 里的中文注释/字面量 | 可保持 UTF-8（文件头有 BOM），与 `ReplacementFuncs.h` 分开管理 |

---

## 3. `SwitchChinese` 配置说明

| 值 | 效果 |
|----|------|
| `true` | 启用字符串池汉化 + `FixDateFormat` / `FixItemType` 等中文相关补丁（**北斗正常使用**） |
| `false` | 使用客户端原始英文 StringPool；界面变英文 |

索引 `1163`（窗口标题）在汉化循环**之后**强制为 `"MapleStory"`，避免被 `{1163,"北斗"}` 覆盖。

## 4. 同批次其他踩坑（简表）

| 现象 | 原因 | 解决 |
|------|------|------|
| 启动失败 `0x80004005`（E_FAIL） | Win10/11 下 DX8 全屏初始化失败；去掉 `UpdateResolution()` 后连窗口模式补丁也没了 | 使用 `ApplyNativeResolution()` + `config.ini` 中 `WindowedMode=true` |
| 登录框/快捷栏比例不对 | `Login.img` / `StatusBar.img` 被换成 1280 宽屏资源 | 用 ImgPatch 从 Royals 合并回 800×600 的 `frame` 和 8 格 `quickSlot` |
| 关汉化后变英文 | 误把乱码当成「汉化本身有问题」 | 修编码，保持 `SwitchChinese=true` |
